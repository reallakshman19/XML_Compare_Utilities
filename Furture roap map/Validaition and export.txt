# Prompt for Coding Agent: Audit the CAD Canvas Implementation

**Context:**
A previous agent has just completed the implementation of the "CAD Canvas Upgrade" (migrating our pipeline graph from static SVGs to a stateful HTML5 Canvas architecture). Before we proceed to build the Validation Engine or Data Persistence features on top of it, we must rigorously audit the Canvas architecture to ensure it is stable, performant, and correctly bound to our data models.

**Your Task:**
Perform a comprehensive code audit and functional test of the newly implemented Canvas architecture in `pipeline-3d-model-preview.js` and `pipeline-3d-model-samples.js`. 

Please execute the following audit checklist and provide a detailed markdown report of your findings. If you find any critical failures, implement the fixes immediately.

### Audit Checklist:

#### 1. Architecture & State Management
*   **Audit Goal:** Verify the Canvas is completely decoupled from the raw string generation.
*   **Check:** Does `PipelineCanvasManager` maintain an internal JavaScript object model (e.g., `nodes[]` and `edges[]`)? 
*   **Check:** When `syncSplitTables()` fires, does it completely destroy and recreate the canvas, or does it intelligently update the `nodes[]` array and call `requestAnimationFrame(render)`? (It *must* do the latter for performance).

#### 2. Two-Way Data Binding (Inverse Math)
*   **Audit Goal:** Verify that dragging a node on the canvas accurately updates the raw text tables.
*   **Check:** Simulate a `pointermove` event on a Z-depth node in the Table 3X Canvas.
*   **Check:** Does the math correctly invert the pixel `Y` coordinate back into a negative underground depth value (e.g., `-1.5`)? 
*   **Check:** Does the `pointerup` event successfully write that `-1.5` value back into the `table3a-raw` `<textarea>` without causing an infinite recursive loop with `syncSplitTables`?

#### 3. Performance & Memory Leaks
*   **Audit Goal:** Ensure the canvas can handle rapid updates without crashing the browser.
*   **Check:** Open `pipeline-3d-model-samples.js`. Are the `pointerdown`, `pointermove`, and `pointerup` listeners attached to the `window` or `document` being properly removed when the modal is closed? 
*   **Check:** Search for `requestAnimationFrame`. Is the render loop running constantly (wasting CPU), or does it only fire when a `dirty` flag is set during dragging? It *must* only render on a dirty flag.

#### 4. Event Delegation for Future Upgrades
*   **Audit Goal:** Verify the Canvas is ready to accept the upcoming "Validation Engine".
*   **Check:** Does the `PipelineCanvasManager` emit custom events (like `canvas:nodeMoved` or `canvas:geometryUpdated`)? If these events do not exist, **implement them now**. The upcoming Validation Engine will completely rely on listening to these specific custom events.

### Output Deliverable:
Provide a markdown report titled `# Canvas Audit Results`. List each check as `[PASS]` or `[FAIL]`. For every `[FAIL]`, provide the root cause and automatically push a commit that fixes the underlying code. Do not submit the audit as complete until all checks are passing.

# Prompt for Coding Agent: Canvas-Based Validation Engine

**Context:**
We have recently upgraded our pipeline 3D modeler from static SVGs to a fully stateful, Object-Oriented HTML5 `<canvas>` architecture (using `Table2XCanvas`, `Table3XCanvas`, and a central `PipelineCanvasManager`). We now need to build a **Real-Time Engineering Validation Engine** that lives directly inside this CAD environment.

The canvas maintains an internal state model of `nodes` (points like V-elevations, Z-depths, Markers) and `edges` (the pipe segments connecting them). It emits events like `nodeMoved` and `nodeAdded`.

**Your Task:**
Implement a live physics/constraints checker that validates the pipeline geometry in real-time as the user drags nodes around the canvas, turning violating elements red and displaying CAD-like tooltip warnings.

Please execute the following steps exactly as described:

### Step 1: Implement the Validation Configuration Panel
Create a new floating UI panel over the canvas called **"Design Constraints"**.
1.  Add inputs for:
    *   `Max Slope (%)`: Default `15.0`.
    *   `Min Soil Cover (m)`: Default `1.2`.
2.  Bind these inputs to a central `ValidationState` singleton (e.g., `PipelineCanvasManager.constraints`).
3.  Whenever these inputs change, dispatch a `constraintsUpdated` custom event on the canvas.

### Step 2: Build the Real-Time Validation Loop
Inside the `PipelineCanvasManager`, listen for the `nodeMoved`, `nodeAdded`, and `constraintsUpdated` events. Attach a `validateGeometry()` routine to these events (debounce by `16ms` to maintain 60fps dragging).

Inside `validateGeometry()`:
1.  **Slope Checker:** Iterate through all `edges` in the `Table2XCanvas` model.
    *   Calculate slope: `Math.abs((edge.nodeB.y - edge.nodeA.y) / (edge.nodeB.x - edge.nodeA.x)) * 100`.
    *   If `slope > constraints.maxSlope`:
        *   Set `edge.state.hasViolation = true`.
        *   Set `edge.state.violationMessage = 'Slope exceeds maximum limit (' + slope.toFixed(1) + '%)'`.
    *   Else, `edge.state.hasViolation = false`.
2.  **Depth Checker:** Iterate through all `Z-depth nodes` in the `Table3XCanvas` model.
    *   If `node.type === 'depth'` and `node.value < 0` (underground) and `Math.abs(node.value) < constraints.minCover`:
        *   Set `node.state.hasViolation = true`.
        *   Set `node.state.violationMessage = 'Insufficient soil cover (' + Math.abs(node.value).toFixed(2) + 'm)'`.
    *   Else, `node.state.hasViolation = false`.

### Step 3: Implement the Canvas Rendering Overrides
Update the `render()` loop inside the Canvas classes to visually broadcast these violations.
1.  **Edge Rendering:** When looping through `edges` to draw the pipe, check `if (edge.state.hasViolation)`. If true, override the default blue stroke with a thick, glowing red stroke (`ctx.strokeStyle = '#ef4444'; ctx.lineWidth = 4; ctx.shadowColor = 'red'; ctx.shadowBlur = 5;`).
2.  **Node Rendering:** When drawing `nodes`, check `if (node.state.hasViolation)`. If true, override the node fill to red and pulse the radius (optional animation step).
3.  **CAD Tooltips:** If the user hovers the cursor over an edge or node where `hasViolation === true`, render a floating canvas tooltip (a small rounded rectangle near the cursor) containing the `violationMessage`.

### Step 4: Sync Violations to the Table Outputs
Because we maintain two-way binding with the raw text tables:
1.  Expose an array of `PipelineCanvasManager.currentViolations` containing the `H(coor)` IDs of broken nodes/edges.
2.  In the standard `renderEditablePreview` and `renderTsvGrid` functions, check this array. If a row's ID exists in the violations array, apply a red background (`background: rgba(239, 68, 68, 0.3); border-left: 3px solid #ef4444;`).

### Definition of Done:
- The engineer drags a Z-depth node upwards. The moment the node crosses the `-1.2m` threshold, the node instantly turns red on the canvas.
- Hovering over that red node immediately displays a canvas tooltip reading *"Insufficient soil cover (1.15m)"*.
- The exact row for that node in the underlying TSV table simultaneously flashes red.

# Prompt for Coding Agent: Data Persistence & Project Branching

**Context:**
Our Pipeline 3D Modeler currently stores all of its critical layout data inside volatile DOM `<textarea>` elements (`table1`, `table2a-raw`, etc.). If the engineer refreshes the browser, they lose hours of work. Furthermore, there is no way to safely test alternative pipeline routes without overwriting the main design. 

**Your Task:**
Implement a robust local database using IndexedDB to automatically save the engineer's work. Add a "Project Branching" feature so they can test alternative designs, and implement a robust `Ctrl+Z` Undo/Redo stack.

Please execute the following steps exactly as described:

### Step 1: Initialize the Local Database (IndexedDB)
At the top of `pipeline-3d-model-samples.js` (or in a new `pipeline-db.js` module), initialize an IndexedDB wrapper (you may use native IndexedDB APIs).
1.  **Schema Definition:** Create an object store called `Workspaces`.
2.  **Data Structure:** Each record should look like:
    ```json
    {
      "id": "project-alpha",
      "activeBranchId": "branch-main",
      "branches": {
        "branch-main": {
          "name": "Base Design",
          "data": { "table1": "...", "table2a-raw": "..." }
        }
      }
    }
    ```

### Step 2: Implement Auto-Save and Hydration
1.  **Hydration (On Load):** When `patchPipelineDialog` initializes, query IndexedDB for the last active project. If it exists, inject the saved string data into all respective `textarea` elements, then call `syncSplitTables(dialog)` to render the graphs.
2.  **Auto-Save (Debounced):** Add a global `input` listener to the dialog. Whenever an input is detected, use a `1000ms` debounce timer. When the timer fires, scrape the `.value` of all critical textareas and `put()` them into the `activeBranch` record in IndexedDB.
3.  **Visual Indicator:** Add a small `<span>` near the top of the dialog that briefly flashes *"Saved locally"* whenever the debounce timer fires successfully.

### Step 3: Implement Project Branching UI
Engineers need to test alternative pipeline routes without destroying the base design.
1.  **Inject the Branch Menu:** At the top of the application (near the "Run" button), inject a small dropdown `<select id="p3d-branch-select">` and a button `<button id="p3d-branch-clone">Clone Route</button>`.
2.  **Clone Logic:** When the user clicks "Clone Route", prompt for a new branch name (e.g., "Bypass Option B"). Duplicate the entire `data` object of the currently active branch, save it as a new branch in IndexedDB, update `activeBranchId`, and update the dropdown.
3.  **Switch Logic:** When the user changes the dropdown selection, scrape the newly selected branch's data from IndexedDB, replace all textarea values, and call `syncSplitTables(dialog)` to redraw the entire application with the alternative route.

### Step 4: Implement the Undo/Redo Stack (Ctrl + Z)
Professional engineering tools require a safety net.
1.  **The History Array:** Create a global `const HistoryStack = []; let historyIndex = -1;`.
2.  **Pushing State:** Whenever a Canvas drag operation finishes (`pointerup`) or a user finishes typing in a textarea (`blur`), take a snapshot of all textarea values and push it onto the `HistoryStack`. Max size: 50 snapshots.
3.  **Keyboard Listeners:** Attach a `keydown` listener to the document. 
    *   If `Ctrl + Z` (or `Cmd + Z`) is pressed: decrement `historyIndex`, fetch the snapshot, replace the textarea values, and call `syncSplitTables()`.
    *   If `Ctrl + Y` (or `Cmd + Shift + Z`) is pressed: increment `historyIndex` (Redo).

### Definition of Done:
- The user can work for 10 minutes, close the browser tab completely, reopen the app, and their exact pipeline design will instantly load back on the screen.
- The user can click "Clone Route", drastically modify the 3D pipeline on the new branch, and then use the dropdown to instantly toggle back and forth between the two designs.
- If the user deletes a vital node by mistake, pressing `Ctrl+Z` instantly restores the node and redraws the graph.
# Prompt for Coding Agent: Professional Import & Export Ecosystem

**Context:**
Our Pipeline 3D Modeler currently requires engineers to manually copy and paste raw TSV text from Excel into `<textarea>` elements. Furthermore, the final output is trapped inside the browser. To make this a professional suite, we need to allow seamless data ingestion directly from Excel files, and we must allow engineers to export their designs into AutoCAD (`.dxf`) and client-ready `.pdf` reports.

**Your Task:**
Implement an automated Import/Export ecosystem. Add drag-and-drop Excel importing, build an ASCII `.dxf` generator for the 2D pipeline layout, and integrate a PDF report generator.

Please execute the following steps exactly as described:

### Step 1: Implement Drag-and-Drop Excel Ingestion
1.  **Import SheetJS:** Inject the SheetJS (xlsx) library via CDN into the application.
2.  **Global Dropzone:** Attach a `drop` and `dragover` event listener to the main `pipeline-3d-model-dialog` container. 
    *   When an engineer drops an `.xlsx` file anywhere on the app, intercept it.
3.  **Data Mapping:** Parse the workbook. Look for specific sheet names (e.g., `Sheet_Table2A`, `Sheet_Table3A`). 
    *   Convert the rows of those sheets into TSV strings.
    *   Inject the TSV strings directly into the respective `table2a-raw`, `table3a-raw` textareas.
    *   Automatically call `syncSplitTables(dialog)` to instantly generate the 3D model from the dropped file.

### Step 2: Implement AutoCAD DXF Export
Engineers need to drop our visual pipeline layouts directly into AutoCAD.
1.  **Export Button:** Add a prominent **"Export to CAD (.dxf)"** button near the top of the application.
2.  **The DXF Generator:** Create a new function `generatePipelineDXF(table2X)`. DXF is a plain ASCII format. You do not need a massive external library for basic lines.
    *   Initialize the standard DXF `HEADER` and `ENTITIES` sections.
    *   Loop through the interpolated `H_Int` and `V_Int` coordinates in `table2X`.
    *   Create a DXF `LWPOLYLINE` entity connecting all the points (representing the main pipeline).
    *   Iterate through the Markers (from Table 3C) and place DXF `TEXT` and `CIRCLE` entities at their respective scaled coordinates.
3.  **Download Trigger:** Encode the generated DXF string as a `Blob` (`type: "text/plain"`), create a hidden `<a>` tag, and automatically download `pipeline_layout.dxf`.

### Step 3: Automated PDF Deliverable Generation
Clients need a summary report of the pipeline design.
1.  **Import jsPDF:** Inject `jspdf` and `html2canvas` via CDN.
2.  **Report Button:** Add a **"Generate PDF Report"** button next to the DXF button.
3.  **The Report Builder:** When clicked:
    *   **Page 1 (Cover):** Print a large title "Pipeline Route Summary", the current date, and a summary of Total Pipeline Length (calculated from the final H-coordinate).
    *   **Page 2 (Visuals):** Use `html2canvas` to take a high-resolution screenshot of the rendered Canvas/SVG graphs (Table 2X Profile and Keyplan) and embed them into the PDF.
    *   **Page 3 (BOM):** Iterate through the Table 3C raw data and generate a clean PDF table titled "Bill of Materials: Structural Markers", listing every `PM-XXX` marker and its absolute `H(coor)`.
4.  **Download Trigger:** Call `pdf.save('Pipeline_Report.pdf')`.

### Definition of Done:
- The user can drag an Excel file from their desktop and drop it onto the browser window. The app instantly parses the sheets and draws the pipeline layout without a single click.
- The user clicks "Export to CAD", opens the downloaded `.dxf` file in AutoCAD, and sees a continuous polyline representing the exact Table 2X pipeline profile they just designed.
- The user clicks "Generate PDF" and instantly receives a 3-page, client-ready summary document containing screenshots of their layout and a table of their markers.
