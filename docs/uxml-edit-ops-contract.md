# UXML edit-ops original-byte patch-back — contract v1

Schema: uxml-edit-ops/v1. **XCU is the only original-file writer.**
TopoFix lane A emits edit operations against its UXML hub; lane C later
transfers validated original-source output to CII. No S4.2 or B7/B8 behavior
is changed by this independent entry point.

## API and envelope

Entry point: uxml/UxmlEditOpsPatchBack.js: applyUxmlEditOps(originalText,
payload,{fileSha256}) — async, returns a structured result. No disk writes.

- originalText: exact UTF-8 original CAESAR II InputXML text (BOM, LF, CRLF).
- fileSha256: lowercase SHA-256 of *measured* original bytes (not a claim).
- payload, exact top-level keys: schema, sourceFormat, fileSha256, policy, ops.
- schema is uxml-edit-ops/v1; sourceFormat is INPUT_XML for implemented kind.
- Each op has exactly: opId, kind, sourceActionId, fileSha256, targets,
  params. opId is UXML-OP- plus its sourceActionId, and both SHA values must
  match the original.
- policy is TopoFix-compatible, with selected_action_ids equal to the exact
  operation sourceActionId set, apply_all_safe false, minimum_confidence 0.95,
  require_no_blocking_plan_actions true, empty joint_repairs and
  short_element_requests. No unknown fields or widening.

Example (the hash is a placeholder and must be actual source SHA to pass):

    {
      "schema": "uxml-edit-ops/v1",
      "sourceFormat": "INPUT_XML",
      "fileSha256": "<sha256-of-original-utf8-bytes>",
      "policy": {
        "selected_action_ids": ["SYNTH-ALIAS-40-20"],
        "apply_all_safe": false,
        "minimum_confidence": 0.95,
        "require_no_blocking_plan_actions": true,
        "joint_repairs": [],
        "short_element_requests": []
      },
      "ops": [{
        "opId": "UXML-OP-SYNTH-ALIAS-40-20",
        "kind": "ALIAS_COINCIDENT_NODE",
        "sourceActionId": "SYNTH-ALIAS-40-20",
        "fileSha256": "<same-sha>",
        "targets": ["<exact-incident-S3-physical-recordKeys>"],
        "params": [{
          "operation": "ALIAS_NODE",
          "sourceNode": 40,
          "canonicalNode": 20
        }]
      }]
    }

Both node parameters are distinct positive safe integers or unambiguous
positive decimal strings. There is exactly one alias instruction per op.
targets must be unique and equal to the complete set of original recordKeys
incident on either absorbed sourceNode or retained canonicalNode. Unknown or
extra target keys refuse. Original strict S3 sourceRefs determine membership:

    {format:"INPUT_XML",fileSha256,recordKey,elementIndex,fromNode,toNode}

recordKey uses E{zeroBasedPhysicalOrdinal}:F{encoded-FROM_NODE}:T{encoded-TO_NODE}.
They are regenerated by strict S3 over measured original bytes and cannot be
supplied as unverified replacement UXML records. No source node occurrence
may remain unaccounted for; no physical PIPINGELEMENT is deleted.

## Implemented kinds and future kinds

| sourceFormat | kind | v1 status |
|---|---|---|
| INPUT_XML | ALIAS_COINCIDENT_NODE | IMPLEMENTED — changes existing FROM_NODE/TO_NODE value spans only |
| INPUT_XML | VALUE_EDIT / DELETE_ELEMENT / ADD_ELEMENT / NODE_MERGE / DROP_SHORT_ELEMENT / REVIEW_CONNECTION / other kinds | REFUSED — UXML_EDIT_OP_KIND_NOT_IMPLEMENTED |
| PSI116 | all kinds including ALIAS_COINCIDENT_NODE | REFUSED — UXML_PSI116_PATCH_NOT_IMPLEMENTED |
| other formats | all kinds | REFUSED — UXML_SOURCE_FORMAT_NOT_IMPLEMENTED |

The logical coincident-node alias is NOT element deletion or structural
markup rewriting. Direct value edits through Categorized S4.2 remain a
different, unchanged API.

## Outputs, byte identity and ledger

On success:

    {ok:true,bytes:Uint8Array,parity:"EQUAL",
     ledger:[{opId,kind,recordKey,field,before,after,
              byteRange:{start,end}}],refusals:[]}

Each ledger entry refers to the original recordKey and to the precise
original existing FROM_NODE or TO_NODE XML attribute value. before and after
are lexical values; after retains the original number of fractional digits.
byteRange uses half-open byte offsets into the **original UTF-8 byte array**.
Disjoint edits are applied right-to-left, preserving BOM, LF/CRLF, whitespace,
all non-target attributes, headers and every byte outside ledger spans.

On any refusal (including multi-op preflight or final parity failure):

    {ok:false,bytes:null,parity:"DIFFERENT",
     ledger:[],refusals:[{code,...location}]}

No partial bytes, ledger or file writes can escape. The caller may persist
the new bytes only on success after its own authorized transaction check.

## Fail-closed custody and parity

1. Require exact v1 payload, explicit action selection and unwidened policy.
2. Independently measure original UTF-8 SHA and match options, payload, ops.
3. Reread the original with XCU main strict S3 and original structural scanner.
   Authenticate physical row order and exact sourceRef identities.
4. Reject forged/missing/extra targets, unknown records, invalid alias params,
   duplicated or overlapping source-node edits.
5. Check every source row, including unselected rows, for stranded child
   NODE/NODE1/CNODE and other numbered NODE attributes; reject SIF owners and
   lossContract.raw witnesses, and prevent planned FROM==TO self-loops.
6. Patch exact original FROM_NODE/TO_NODE byte-value spans only, never rebuild.
7. Independently hash and reread candidate with strict S3. Require the same
   PIPINGELEMENT count, precisely planned node endpoint identities, and exact
   equality of every non-ledger byte. Only then return parity EQUAL.

## Authorization boundary

The v1 envelope has no signature proving a claimed sourceActionId was
generated by a specific TopoFix engine run. The XCU JS patcher can validate
sourceRef and original-byte authority, target completeness, strict policy
shape, exact alias semantics, and post-patch parity. It **cannot claim**
to have performed TopoFix's native findings/preflight/transaction validation.
The action-producer boundary must enforce that upstream; do not treat
arbitrary user-authored envelopes as engineering approval. A signed
engine-action attestation would require a separately reviewed v2 contract.

TopoFix DRAFT #23 at 396bd2aa (independent PASS 93) is a reference port,
not a second writer. Its Python native analyzer remains independent; XCU S3
is the only reader used by this entry point.
